# Теория и устройство программы для лабораторной работы 4

## Что делает программа

Программа строит изображение трехмерной сцены методом трассировки путей
(`path tracing`). Это разновидность трассировки лучей (`ray tracing`), в которой
для каждого пикселя выпускается не один детерминированный луч, а набор
случайных лучей. Каждый луч может несколько раз отражаться от поверхностей,
поэтому в изображении учитывается не только прямое освещение от источников,
но и глобальное освещение: переотражения света между объектами сцены.

Итоговая схема вычисления такая:

```text
камера -> первичный луч -> пересечение со сценой
       -> материал поверхности
       -> прямой свет от area light
       -> случайное отражение
       -> следующий луч
       -> накопление яркости
```

Если луч попадает в источник света, его излучение добавляется в цвет пикселя.
Если луч не попадает ни в один объект, вклад считается нулевым.

## Используется ли ray tracing

Да. В программе используется трассировка лучей, но не в классическом простом
варианте "луч от камеры - объект - источник", а в более общем варианте:
`path tracing`.

Разница:

```text
Ray tracing:
    обычно считает прямую видимость, тени, отражения и преломления
    по заданным правилам.

Path tracing:
    строит случайные пути света и оценивает освещенность методом Монте-Карло.
```

В нашей программе каждый путь начинается в камере, а дальше случайно
продолжается по сцене. Поэтому метод называется обратной трассировкой путей:
мы идем не от источника света к камере, а от камеры в сцену.

## Геометрия сцены

По заданию геометрия должна быть треугольной сеткой. Поэтому все объекты
сцены представлены треугольниками.

В коде есть базовые сущности:

```text
Vec3      - трехмерный вектор или RGB-цвет;
Ray       - луч, заданный начальной точкой и направлением;
Triangle  - треугольник сцены;
Material  - материал поверхности;
Hit       - результат пересечения луча с поверхностью;
Scene     - список треугольников и список светящихся треугольников.
```

Прямоугольники создаются как два треугольника. Кубы создаются как шесть
прямоугольных граней, то есть как двенадцать треугольников. Пирамида задается
основанием и четырьмя боковыми треугольниками.

В программе есть две сцены:

```text
gallery  - основная сцена: световая галерея с зеркальной пирамидой;
cornell  - контрольная сцена в стиле Cornell box.
```

Основной вариант - `gallery`, потому что он менее шаблонный и лучше отличается
от типичных демонстрационных сцен.

## Камера

Камера является точечной. Она задается:

```text
position - положение камеры;
look_at  - точка, куда камера смотрит;
up       - направление вверх;
fov      - угол обзора;
aspect   - отношение ширины изображения к высоте.
```

Для каждого пикселя камера строит первичный луч. Координата внутри пикселя
выбирается случайно:

```text
u = (x + random()) / width
v = (y + random()) / height
```

Это дает антиалиасинг. Если для пикселя выпущено много лучей, они проходят
через разные случайные точки внутри пикселя, а результат усредняется.

## Пересечение луча с треугольником

Для поиска пересечения используется алгоритм Моллера-Трумбора
(`Moller-Trumbore`). Он решает задачу:

```text
ray.origin + t * ray.direction = A + u * (B - A) + v * (C - A)
```

где:

```text
A, B, C - вершины треугольника;
t       - расстояние от начала луча до точки пересечения;
u, v    - барицентрические координаты внутри треугольника.
```

Пересечение существует, если:

```text
t > 0
u >= 0
v >= 0
u + v <= 1
```

Для каждого луча программа проверяет все треугольники и выбирает ближайшее
пересечение. Так находится первая видимая поверхность на пути луча.

## Материалы

Материал задает три компоненты:

```text
diffuse  - диффузное отражение по модели Ламберта;
mirror   - зеркальное отражение;
emission - собственное излучение поверхности.
```

Диффузная поверхность рассеивает свет во все стороны над поверхностью.
Зеркальная поверхность отражает луч строго по закону отражения.
Светящаяся поверхность является протяженным источником света.

Важное физическое ограничение:

```text
diffuse[channel] + mirror[channel] <= 1
```

Это означает, что поверхность не может отразить больше энергии, чем получила.
В программе это проверяется методом `Material.validate()`.

## Диффузное отражение

Для диффузного отражения используется модель Ламберта. Ее BRDF:

```text
BRDF = diffuse_color / pi
```

Новое направление луча выбирается случайно в полусфере над поверхностью.
Выборка не равномерная, а косинусная: направления около нормали выбираются
чаще, чем направления почти вдоль поверхности. Это соответствует физической
модели Ламберта и уменьшает шум.

В программе это делает функция:

```text
sample_cosine_hemisphere(normal, rng)
```

## Зеркальное отражение

Для зеркального материала новое направление вычисляется по формуле отражения:

```text
reflected = direction - 2 * dot(direction, normal) * normal
```

То есть угол падения равен углу отражения. Это используется для зеркальной
пирамиды в сцене `gallery`.

## Русская рулетка

Луч не может отражаться бесконечно, поэтому используется ограничение глубины
и русская рулетка.

На каждом столкновении программа случайно выбирает событие:

```text
диффузное отражение;
зеркальное отражение;
поглощение луча.
```

Вероятность события зависит от коэффициентов материала. Если материал хорошо
отражает свет, луч чаще продолжает путь. Если отражение слабое, луч чаще
поглощается.

Чтобы оценка яркости оставалась корректной, вклад луча делится на вероятность
выбранного события. Это стандартная идея Монте-Карло:

```text
оценка = вклад / вероятность_выбора
```

## Источники света

В задании требуются протяженные источники света. В программе источники света
тоже являются треугольниками или прямоугольниками из двух треугольников.

Светящиеся материалы имеют ненулевой параметр:

```text
emission = RGB-яркость
```

В сцене `gallery` используются:

```text
левая голубая световая панель;
правая теплая световая панель;
мягкий потолочный источник.
```

Источник выбирается случайно с учетом его мощности:

```text
weight = luminance(emission) * area
```

То есть большие и яркие источники выбираются чаще.

## Прямое освещение

Если использовать только случайные переотражения, лучи редко будут попадать
в источник света, особенно если источник небольшой. Из-за этого изображение
будет очень шумным.

Поэтому программа отдельно оценивает прямое освещение:

```text
точка поверхности -> случайная точка на источнике света
```

После выбора точки на источнике проверяется:

```text
виден ли источник из данной точки;
не перекрыт ли он другим объектом;
под каким углом свет падает на поверхность;
под каким углом источник излучает в сторону поверхности.
```

Формула вклада содержит геометрический множитель:

```text
G = cos_surface * cos_light / distance^2
```

где:

```text
cos_surface - угол между нормалью поверхности и направлением на свет;
cos_light   - угол между нормалью источника и направлением к поверхности;
distance    - расстояние между точками.
```

Также учитывается вероятность выбора источника и точки на нем. Поэтому итоговая
оценка прямого света имеет вид:

```text
emission * BRDF * G / pdf
```

## Накопление яркости

Функция трассировки хранит две величины:

```text
radiance   - накопленная яркость;
throughput - текущий вес пути.
```

`throughput` показывает, какая часть энергии дошла до текущего шага. При каждом
отражении он умножается на цвет материала и корректируется на вероятность
выбранного события.

Упрощенно:

```text
radiance += throughput * direct_light
throughput *= material_color / event_probability
```

Если луч попадает в светящуюся поверхность:

```text
radiance += throughput * emission
```

После этого путь завершается.

## Почему появляется шум

Шум появляется из-за метода Монте-Карло. Каждый пиксель оценивается по
случайным лучам. При малом числе лучей оценка грубая, поэтому соседние пиксели
могут сильно отличаться.

Если увеличить число лучей на пиксель (`samples per pixel`), шум уменьшается:

```text
1-4 spp     - очень шумно, быстрый предпросмотр;
16 spp      - сцена уже читается;
32-64 spp   - приемлемый черновой результат;
128+ spp    - заметно чище, но расчет дольше.
```

Скорость уменьшения шума примерно такая:

```text
noise ~ 1 / sqrt(N)
```

То есть чтобы уменьшить шум в два раза, нужно примерно в четыре раза увеличить
число лучей.

## Формирование итогового изображения

Path tracer считает цвет в вещественных значениях RGB. Это не готовые значения
`0..255`, а физически похожие яркости:

```text
0.0, 0.5, 1.2, 8.0 ...
```

Перед сохранением выполняются шаги:

1. Умножение на экспозицию.
2. Ограничение значений в диапазоне `0..1`.
3. Гамма-коррекция.
4. Перевод в диапазон `0..255`.
5. Запись в `PPM`, опционально в `PNG`.

Гамма-коррекция:

```text
V_corrected = V ^ (1 / gamma)
```

Обычно используется:

```text
gamma = 2.2
```

Без гамма-коррекции изображение выглядело бы слишком темным, потому что монитор
и человеческое зрение воспринимают яркость нелинейно.

## Интерфейс программы

Программа поддерживает два режима:

```text
GUI - графический интерфейс на tkinter;
CLI - запуск через параметры командной строки.
```

В GUI можно изменить:

```text
размер изображения;
сцену;
число лучей на пиксель;
максимальную глубину пути;
экспозицию;
гамму;
seed генератора случайных чисел;
путь сохранения результата.
```

Это соответствует требованию задания о простом интерфейсе, позволяющем менять
параметры сцены и получать новый результат во время защиты.

## Что можно показать в отчете

Для демонстрации корректности можно привести:

```text
1. Схему сцены и список материалов.
2. Изображения при разном числе samples per pixel.
3. Объяснение, что шум уменьшается при росте числа лучей.
4. Пример цветного переотражения от боковых световых панелей.
5. Пример зеркального отражения на пирамиде.
6. Описание проверки физичности материалов.
7. Описание gamma correction и сохранения изображения.
```

Главный вывод: программа реализует не просто отрисовку треугольников, а
стохастическую трассировку путей с учетом прямого света, непрямого света,
диффузных и зеркальных отражений.
