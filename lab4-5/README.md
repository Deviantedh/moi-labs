# ЛР 5

Эта папка содержит актуальную версию лабораторной работы 5.

Основа взята из `lab4/lab4.py`: программа строит изображение сцены методом path tracing. Поверх результата добавлена лабораторная 5: сохранение буферов первого пересечения и билатеральная фильтрация.

## Что добавлено к ЛР 4

В режиме `--lab5` программа сохраняет:

- `render_noisy.png` - исходный шумный path tracing render;
- `render_filtered.png` - результат билатеральной фильтрации;
- `direct.png` - прямая яркость;
- `secondary.png` - вторичная яркость от продолжения путей;
- `depth.png` - карта глубины первого пересечения;
- `normal.png` - карта нормалей первого пересечения;
- `object_id.png` - карта объектов;
- `results_lr4_5.txt` - проверка сохранения суммарной яркости по объектам.

## Как запустить

Быстрый тест:

```bash
python3 lab4_5.py --cli --lab5 --width 120 --height 120 --samples 1 --depth 3 --scene gallery --lab5-output-dir lab5_results
```

Более чистый вариант:

```bash
python3 lab4_5.py --cli --lab5 --width 220 --height 220 --samples 4 --depth 5 --scene gallery --lab5-output-dir lab5_results
```

Обычная ЛР 4 без фильтрации по-прежнему работает:

```bash
python3 lab4_5.py --cli --width 500 --height 500 --samples 4 --depth 6 --scene gallery --png
```

## Смысл реализации

ЛР 4 уже выполняет path tracing. Поэтому для ЛР 5 больше не нужно задавать `direct`, `secondary`, `depth`, `normal` и `object_id` искусственно. В новой версии они берутся из рендера:

- `direct` - прямой свет на первой видимой поверхности;
- `secondary` - вклад света после продолжения пути;
- `depth` - расстояние до первой точки пересечения луча со сценой;
- `normal` - нормаль первой видимой поверхности;
- `object_id` - номер объекта, которому принадлежит первая видимая поверхность.

Далее прямой и вторичный буферы фильтруются отдельно, складываются и нормируются по суммарной яркости каждого объекта.
