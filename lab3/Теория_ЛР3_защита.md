# Теория к защите ЛР3 по МОИ

## Что Нужно Понять В Этой Лабе

Тема лабораторной: формирование распределения случайных величин в заданной области определения.

В работе нужно было получить четыре типа выборок:

1. Равномерные точки внутри треугольника.
2. Равномерные точки внутри круга.
3. Равномерные направления на единичной сфере.
4. Направления с косинусным распределением относительно нормали.

Все четыре задачи решаются одной общей идеей: мы берем простые равномерные случайные числа `xi` из `[0, 1)` и преобразуем их так, чтобы итоговая точка имела нужную плотность вероятности.

В методичке `3275.pdf` это относится к разделу 4.7 "Формирование случайных величин с заданным PDF":

- 4.7.1 - равномерное распределение случайной координаты на плоских фигурах;
- 4.7.2 - равномерное распределение точек на поверхности сферы;
- 4.7.4 - распределение лучей с заданной плотностью вероятности.

Главный принцип:

```text
равномерность случайных чисел не всегда означает равномерность точек в геометрической области
```

Например, если равномерно выбрать радиус круга, точки не будут равномерны по площади. Если равномерно выбрать угол `theta` на сфере, точки не будут равномерны по поверхности сферы. Поэтому нужно учитывать элемент площади или элемент телесного угла.

## Базовые Понятия

### Случайная Величина

Случайная величина - это результат случайного эксперимента. В этой работе случайными величинами являются:

- координаты точки внутри треугольника;
- координаты точки внутри круга;
- координаты единичного направления на сфере;
- координаты направления в полусфере с косинусной плотностью.

В коде первичные случайные величины получаются через:

```python
random.random()
```

Эта функция возвращает число из `[0, 1)`.

### Плотность Вероятности

Плотность вероятности показывает, насколько часто случайная величина попадает в малую область.

Для непрерывной случайной величины вероятность попадания в малую область примерно равна:

```text
probability ~= density * measure
```

Где `measure` - это длина, площадь или телесный угол, в зависимости от задачи.

Для равномерного распределения плотность постоянна по всей области.

### PDF И CDF

`PDF` - probability density function, плотность вероятности.

`CDF` - cumulative distribution function, функция распределения:

```text
P(x) = integral p(t) dt
```

Если нужно получить случайную величину с заданной плотностью, часто используется метод обратной функции:

```text
xi = P(x)
x = P^{-1}(xi)
```

Именно так получается формула `r = R * sqrt(xi)` для круга.

## 1. Равномерное Распределение Внутри Треугольника

### Что Дано

Треугольник задан тремя точками в пространстве:

```text
A, B, C
```

В нашей программе:

```text
A = (0.0, 0.0, 0.0)
B = (2.0, 0.0, 0.0)
C = (0.5, 1.8, 0.7)
```

Нужно сформировать `100000` точек внутри треугольника.

### Формула Из Методички

В разделе 4.7.1 методички треугольник рассматривается через систему координат по двум сторонам. Берутся две равномерные случайные величины:

```text
u, v ~ U(0, 1)
```

Сначала они задают точку в параллелограмме, построенном на сторонах треугольника.

Критерий попадания в треугольник:

```text
u + v <= 1
```

Если условие выполнено, точка уже внутри треугольника. Если нет, методичка предлагает два варианта:

1. Выборка с отклонением: отбросить точку и сгенерировать новую.
2. Зеркальное отражение: заменить `u` и `v` на `1 - u` и `1 - v`.

Мы используем второй вариант, потому что он дает ровно столько точек, сколько было исходных выборок.

Алгоритм:

```text
u = random()
v = random()

if u + v > 1:
    u = 1 - u
    v = 1 - v

P = A + u * (B - A) + v * (C - A)
```

### Почему Это Равномерно

Параллелограмм, построенный на векторах `(B - A)` и `(C - A)`, равномерно заполняется точками, если `u` и `v` равномерны.

Этот параллелограмм состоит из двух равных треугольников:

- первый: `u + v <= 1`;
- второй: `u + v > 1`.

Если точка попала во второй треугольник, мы отражаем ее в первый. Отражение сохраняет площадь: области одинаковой площади переходят в области одинаковой площади.

Значит, вероятность попадания в любую малую область внутри треугольника пропорциональна ее площади. Это и есть равномерность по площади.

### Почему Все Точки Внутри

После отражения всегда выполняется:

```text
u >= 0
v >= 0
u + v <= 1
```

Это стандартные барицентрические условия принадлежности треугольнику.

Точка строится как:

```text
P = A + u * (B - A) + v * (C - A)
```

Или:

```text
P = (1 - u - v) * A + u * B + v * C
```

Так как коэффициенты неотрицательные и их сумма равна `1`, точка лежит внутри треугольника.

### Что Говорить На Защите

Короткий ответ:

> Я выбираю точку в параллелограмме по двум равномерным координатам. Если она попала во вторую половину параллелограмма, отражаю ее внутрь треугольника. Отражение сохраняет площадь, поэтому распределение внутри треугольника остается равномерным. При этом не происходит отбрасывания точек, поэтому из 100000 выборок получается ровно 100000 точек.

### Возможные Вопросы

**Почему не rejection sampling?**

Можно было бы отбрасывать точки, у которых `u + v > 1`. Но тогда часть выборок теряется. В задании сказано, что число точек в выборке и число сформированных точек должны быть одинаковыми: `100000` и `100000`. Отражение позволяет не терять выборки.

**Почему условие `u + v <= 1` означает попадание в треугольник?**

Потому что `u` и `v` - это две барицентрические координаты относительно вершины `A`. Третья координата равна `1 - u - v`. Для точки внутри треугольника все три барицентрические координаты должны быть неотрицательными.

**Как проверялась равномерность?**

Мы считали число точек в одинаковых прямоугольниках в локальных координатах `(u, v)`. Если распределение равномерное, в одинаковых по площади областях должно быть близкое число точек.

## 2. Равномерное Распределение Внутри Круга

### Что Дано

Круг задан:

```text
центр C
нормаль N
радиус Rc
```

В нашей программе:

```text
C = (-1.0, 0.5, 0.8)
N = (0.2, -0.3, 1.0)
Rc = 1.2
```

### Почему Нужен Локальный Базис

Круг может быть произвольно ориентирован в 3D-пространстве. Поэтому сначала строится локальная система координат в плоскости круга:

```text
T, B, N
```

Где:

- `N` - нормаль круга;
- `T` - единичный вектор в плоскости круга;
- `B` - второй единичный вектор в плоскости круга;
- `T`, `B`, `N` взаимно перпендикулярны.

В коде это делает функция:

```python
get_basis_by_normal(normal)
```

Идея:

1. Нормализуем нормаль `N`.
2. Берем вспомогательный вектор, не параллельный `N`.
3. Через векторное произведение получаем касательный вектор.
4. Второе векторное произведение дает второй касательный вектор.

### Формула Из Методички

В разделе 4.7.1 методички для круга приводятся два способа:

1. Выборка с отклонением из описанного квадрата.
2. Прямое формирование точки в круге через полярные координаты.

Мы используем второй способ.

Формулы:

```text
phi = 2 * pi * xi_phi
r = Rc * sqrt(xi_r)
```

Локальная точка:

```text
P_local = (r * cos(phi), r * sin(phi), 0)
```

Точка в мировой системе координат:

```text
P = C + r * cos(phi) * T + r * sin(phi) * B
```

### Почему Радиус Через Корень

Это самый важный вопрос по кругу.

Если взять:

```text
r = Rc * xi
```

то радиус будет равномерным, но точки по площади круга не будут равномерны. Они будут скапливаться ближе к центру.

Причина: площадь кольца радиуса `r` и толщины `dr` равна:

```text
dS = 2 * pi * r * dr
```

В полярных координатах элемент площади:

```text
dS = r * dr * dphi
```

То есть чем больше радиус, тем больше площадь кольца. Чтобы точки равномерно покрывали площадь, вероятность попасть в радиус до `r` должна быть равна доле площади круга:

```text
P(r) = area of circle with radius r / area of full circle
P(r) = pi * r^2 / (pi * Rc^2)
P(r) = r^2 / Rc^2
```

Теперь применяем метод обратной функции:

```text
xi = P(r) = r^2 / Rc^2
r = Rc * sqrt(xi)
```

Поэтому в коде стоит именно:

```text
r = Rc * sqrt(random())
```

### Почему Все Точки Внутри

Так как:

```text
0 <= xi_r < 1
```

то:

```text
0 <= r < Rc
```

Значит:

```text
x^2 + y^2 = r^2 <= Rc^2
```

Точка всегда лежит внутри круга.

### Что Говорить На Защите

Короткий ответ:

> Для круга я перехожу в локальную плоскость, перпендикулярную нормали. Угол беру равномерно от 0 до 2pi, а радиус беру как Rc * sqrt(xi), потому что площадь в полярных координатах содержит множитель r. Такая формула получается из функции распределения P(r) = r^2 / Rc^2.

### Возможные Вопросы

**Почему не брать радиус равномерно?**

Потому что тогда одинаковые интервалы радиуса получали бы одинаковое число точек, но внешние кольца имеют большую площадь. В результате плотность по площади была бы выше в центре.

**Что проверяется для круга?**

Проверяется:

```text
x^2 + y^2 <= Rc^2
```

в локальных координатах, отклонение от плоскости круга, близость среднего значения к центру и равномерность по равным секторам.

## 3. Равномерное Распределение Направлений На Сфере

### Что Нужно Получить

Нужно сформировать `100000` единичных направлений в пространстве. Это то же самое, что точки на единичной сфере.

Каждое направление:

```text
omega = (x, y, z)
```

должно иметь длину:

```text
|omega| = 1
```

### Почему Нельзя Равномерно Брать `theta`

Если использовать сферические координаты:

```text
x = sin(theta) * cos(phi)
y = sin(theta) * sin(phi)
z = cos(theta)
```

может показаться, что нужно взять:

```text
theta ~ U(0, pi)
phi ~ U(0, 2pi)
```

Но это ошибка.

Элемент площади на сфере:

```text
dS = sin(theta) * dtheta * dphi
```

У полюсов `sin(theta)` маленький, около экватора большой. Поэтому равномерный `theta` даст слишком много точек около полюсов.

### Формула Из Методички

В разделе 4.7.2 методички вводится высота `h` по оси сферы и азимутальный угол `phi`.

Для единичной сферы:

```text
h = 2 * xi_h - 1
phi = 2 * pi * xi_phi
```

В нашей программе используется эквивалентная формула:

```text
z = 1 - 2 * xi
phi = 2 * pi * eta
```

Дальше:

```text
x = sqrt(1 - z^2) * cos(phi)
y = sqrt(1 - z^2) * sin(phi)
omega = (x, y, z)
```

Знак у `z` не важен: `1 - 2xi` и `2xi - 1` оба дают равномерное распределение на `[-1, 1]`.

### Почему Это Равномерно

В методичке площадь сферического сегмента выражается через высоту:

```text
dS = Rs * dphi * dh
```

Для единичной сферы `Rs = 1`, значит:

```text
dS = dphi * dz
```

То есть если `z` равномерно распределен на `[-1, 1]`, а `phi` равномерно на `[0, 2pi)`, то площадь сферических полос выбирается равномерно.

### Теоретическая Плотность Для Проверки

Так как `z` равномерно распределен на отрезке длины `2`, его плотность равна:

```text
p(z) = 1 / 2 = 0.5, z in [-1, 1]
```

Поэтому в отчете и программе строится гистограмма `z` и сравнивается с горизонтальной линией `0.5`.

### Что Говорить На Защите

Короткий ответ:

> Я не выбираю угол theta равномерно, потому что элемент площади сферы содержит sin(theta). Вместо этого я выбираю равномерно высоту z на [-1, 1] и азимут phi на [0, 2pi). Тогда элемент площади записывается как dS = dz dphi, и распределение по сфере получается равномерным.

### Возможные Вопросы

**Почему средний вектор должен быть около нуля?**

Потому что равномерная сфера симметрична. На каждое направление статистически есть противоположное. Поэтому математическое ожидание:

```text
E[omega] = (0, 0, 0)
```

**Почему длина равна единице?**

По формуле:

```text
x^2 + y^2 = 1 - z^2
```

Значит:

```text
x^2 + y^2 + z^2 = 1
```

## 4. Косинусное Распределение Направлений

### Что Нужно Получить

Нужно сформировать направления в полусфере относительно нормали `N`, но не равномерно. Плотность должна быть пропорциональна косинусу угла между направлением и нормалью:

```text
p(omega) ~ cos(theta)
```

Где:

```text
cos(theta) = dot(omega, N)
```

если `omega` и `N` нормированы.

В нашей программе:

```text
N = (0.0, 0.0, 1.0)
```

### Связь С Методичкой

В разделе 4.7.4 методички рассматривается распределение лучей с заданной плотностью вероятности.

Для модели Ламберта:

```text
I(theta) = cos(theta)
```

Это осесимметричная модель, поэтому `phi` равномерно распределен от `0` до `2pi`.

Так как телесный угол в сферических координатах содержит `sin(theta)`, плотность по углу `theta` пропорциональна:

```text
cos(theta) * sin(theta)
```

### Нормированная Плотность По Телесному Углу

Для полусферы нормированная плотность по телесному углу:

```text
p(omega) = cos(theta) / pi
```

Почему делим на `pi`:

```text
integral over hemisphere cos(theta) d omega = pi
```

Значит, чтобы интеграл плотности был равен 1:

```text
p(omega) = cos(theta) / pi
```

### Плотность Для `mu = cos(theta)`

На защите удобно объяснять через:

```text
mu = cos(theta)
```

Для косинусного распределения теоретическая плотность `mu`:

```text
p(mu) = 2 * mu, mu in [0, 1]
```

Проверка нормировки:

```text
integral from 0 to 1 of 2mu dmu = [mu^2]_0^1 = 1
```

Математическое ожидание `mu`:

```text
E[mu] = integral from 0 to 1 mu * 2mu dmu
E[mu] = 2 * integral from 0 to 1 mu^2 dmu
E[mu] = 2/3
```

Поэтому в программе `Mean error` для косинусного распределения сравнивает среднее `mu` с `2/3`.

### Формула В Нашем Коде

Мы используем метод через равномерную точку на единичном диске:

```text
r = sqrt(xi)
phi = 2 * pi * eta

x = r * cos(phi)
y = r * sin(phi)
z = sqrt(1 - r^2)

omega_local = (x, y, z)
```

Потом локальное направление переводится в мировую систему координат так, чтобы локальная ось `z` совпала с нормалью `N`.

### Почему Этот Метод Дает Косинусное Распределение

Есть два способа объяснить.

#### Объяснение Через Проекцию

Мы равномерно выбираем точку на диске `(x, y)`. Затем поднимаем ее на верхнюю полусферу:

```text
z = sqrt(1 - x^2 - y^2)
```

Это ортогональная проекция полусферы на диск.

Малая площадка на полусфере при проекции на диск уменьшается в `cos(theta)` раз:

```text
dA_disk = cos(theta) * dA_sphere
```

Если точки равномерны на диске, то соответствующая плотность на сфере пропорциональна:

```text
cos(theta)
```

Поэтому получается cosine-weighted sampling.

#### Объяснение Через `mu`

На диске:

```text
r^2 = xi
```

На полусфере:

```text
mu = z = sqrt(1 - r^2)
```

Тогда:

```text
r^2 = 1 - mu^2
```

Так как `r^2` равномерно на `[0, 1]`, получаем:

```text
P(Mu <= mu) = mu^2
```

Следовательно:

```text
p(mu) = d(mu^2) / dmu = 2mu
```

Это ровно теоретическая плотность косинусного распределения по `mu`.

### Что Говорить На Защите

Короткий ответ:

> Для косинусного распределения я равномерно выбираю точку на единичном диске и поднимаю ее на полусферу. При ортогональной проекции площадь на сфере связана с площадью на диске через множитель cos(theta), поэтому равномерная плотность на диске переходит в косинусную плотность на полусфере. Проверяю это по гистограмме mu = cos(theta), для которой теория дает p(mu) = 2mu.

### Возможные Вопросы

**Почему направления только в верхней полусфере?**

Потому что:

```text
z = sqrt(1 - r^2) >= 0
```

После поворота это означает:

```text
dot(omega, N) >= 0
```

**Почему среднее `mu` должно быть `2/3`?**

Потому что:

```text
p(mu) = 2mu
E[mu] = integral_0^1 mu * 2mu dmu = 2/3
```

**Почему плотность по `mu` растет линейно?**

Потому что чем больше `mu`, тем направление ближе к нормали. Для ламбертовского косинусного распределения такие направления более вероятны.

## Проверки В Программе

### Inside Ratio

`Inside ratio` - доля точек или направлений, которые удовлетворяют условиям области.

Для треугольника:

```text
u >= 0
v >= 0
u + v <= 1
```

Для круга:

```text
x^2 + y^2 <= Rc^2
```

Для сферы:

```text
|omega| = 1
```

Для косинусного распределения:

```text
|omega| = 1
dot(omega, N) >= 0
```

В результатах `Inside ratio = 1.000000` для всех случаев, значит все выборки корректны.

### Constraint Error

`Constraint error` - средняя ошибка геометрического ограничения.

Для треугольника и круга это отклонение от плоскости:

```text
abs(dot(P - P0, normal))
```

Для сферы и косинусного распределения это отклонение длины направления от единицы:

```text
abs(|omega| - 1)
```

Если ошибка порядка `1e-17`, это практически ноль, то есть машинная погрешность.

### Mean Error

Проверяется среднее значение.

Для треугольника теоретический центр масс:

```text
(A + B + C) / 3
```

Для круга теоретический центр:

```text
C
```

Для сферы теоретическое среднее направление:

```text
(0, 0, 0)
```

Для косинусного распределения:

```text
E[mu] = 2/3
```

### Uniformity Score

Для треугольника это относительный разброс числа точек по одинаковым прямоугольникам. Для круга это относительный разброс числа точек по равным секторам.

Идея:

```text
одинаковая площадь -> примерно одинаковое число точек
```

Для сферы и косинусного распределения это среднее отклонение эмпирической плотности от теоретической:

```text
для сферы: p(z) = 0.5
для косинусного распределения: p(mu) = 2mu
```

## Как Считались Таблицы По Частям Фигур

Это важный момент для защиты: преподаватель может спросить, откуда взялось ожидаемое среднее в таблицах.

### Треугольник

В треугольнике мы считаем не произвольные области, а 8 одинаковых прямоугольников в локальных координатах `(u, v)`.

Локальный треугольник задается условиями:

```text
u >= 0
v >= 0
u + v <= 1
```

Его площадь в координатах `(u, v)`:

```text
S_triangle = 1 / 2
```

Каждый проверочный прямоугольник имеет размеры:

```text
0.2 x 0.2
```

Значит его площадь:

```text
S_rect = 0.04
```

Ожидаемое число точек:

```text
N_expected = N * S_rect / S_triangle
N_expected = 100000 * 0.04 / 0.5 = 8000
```

Ошибка в таблице:

```text
error = N_real - N_expected
```

### Круг

В круге мы используем 8 равных секторов в локальных координатах круга `(x, y)`.

Для каждой точки считается локальный угол:

```text
phi = atan2(y, x)
```

Если `phi < 0`, прибавляем `2pi`, чтобы угол лежал в диапазоне `[0, 2pi)`. Затем круг делится на 8 одинаковых угловых интервалов:

```text
[0;45), [45;90), ..., [315;360)
```

У всех секторов одинаковый угол `2pi / 8`, одинаковый радиус `Rc`, значит одинаковая площадь:

```text
S_sector = S_circle / 8
```

Ожидаемое число точек:

```text
N_expected = N * S_sector / S_circle
N_expected = N / 8
```

При `N = 100000`:

```text
N_expected = 12500
```

Если преподаватель спросит "почему сектора корректны", можно ответить:

> У равных секторов одинаковая площадь, потому что радиус одинаковый и угол каждого сектора одинаковый. Для равномерного распределения по площади вероятность попасть в сектор равна доле его площади: `S_sector / S_circle = 1/8`. Поэтому ожидаемое число точек в каждом секторе равно `N/8`.

### Сфера

В сфере мы не делим ее по обычному углу `theta`, потому что такие части не будут равны по площади.

В таблице мы делим сферу на 8 равных частей: 2 интервала по координате `z` и 4 сектора по азимутальному углу `phi`.

Для единичной сферы:

```text
dS = dz * dphi
```

Берем 2 одинаковых интервала по `z`:

```text
[-1; 0], [0; 1]
```

И 4 одинаковых сектора по `phi`:

```text
[0;90), [90;180), [180;270), [270;360)
```

Так как ширина по `z` одинаковая и ширина по `phi` одинаковая, все 8 частей имеют одинаковую площадь. Вероятность попасть в каждую часть:

```text
P_part = 1 / 8
```

Ожидаемое число точек:

```text
N_expected = N / 8 = 12500
```

Это можно назвать проверкой по равным сферическим частям.

### Косинусное Распределение

Для косинусного распределения проверка идет по интервалам:

```text
mu = cos(theta)
```

Здесь ожидаемое число точек в интервалах не одинаковое.

Теоретическая плотность:

```text
p(mu) = 2mu, 0 <= mu <= 1
```

Для интервала `[mu_left, mu_right]` вероятность:

```text
P_bin = integral from mu_left to mu_right of 2mu dmu
P_bin = mu_right^2 - mu_left^2
```

Ожидаемое число точек:

```text
N_expected = N * (mu_right^2 - mu_left^2)
```

Из-за этого в таблице ожидаемые значения растут: около `mu = 0` точек должно быть мало, около `mu = 1` - много.

## Что Можно Сказать Про Графики

### Треугольник

График показывает точки в локальных координатах `(u, v)`. Видно, что точки заполняют треугольную область без дыр и явного сгущения.

### Круг

График показывает точки в локальных координатах круга. Точки заполняют диск равномерно, без заметного сгущения в центре.

### Сфера

Гистограмма координаты `z` сравнивается с теоретической плотностью:

```text
p(z) = 0.5
```

Если столбцы близки к горизонтальной линии, распределение на сфере равномерное.

### Косинусное Распределение

Гистограмма `mu = cos(theta)` сравнивается с:

```text
p(mu) = 2mu
```

Столбцы должны расти примерно линейно.

### 3D-График

Для сферы 3D-график показывает точки по всей единичной сфере. Это визуальная проверка, что нет провала на полюсах или экваторе.

Для косинусного распределения 3D-график показывает облако направлений в верхней полусфере. Точек визуально больше ближе к нормали, что соответствует косинусному распределению.

## Частые Вопросы Преподавателя И Ответы

### Почему В Круге Используется `sqrt`?

Потому что площадь круга радиуса `r` пропорциональна `r^2`. Для равномерности по площади функция распределения должна быть:

```text
P(r) = r^2 / Rc^2
```

Отсюда:

```text
r = Rc * sqrt(xi)
```

### Почему На Сфере Равномерно Берется `z`, А Не `theta`?

Потому что элемент площади сферы:

```text
dS = sin(theta) dtheta dphi
```

Если брать `theta` равномерно, возникнет сгущение у полюсов. Через замену `z = cos(theta)` элемент площади становится:

```text
dS = dz dphi
```

Поэтому равномерные `z` и `phi` дают равномерную сферу.

### Почему Треугольник Равномерный После Отражения?

Потому что исходно точки равномерны в параллелограмме, а отражение второй половины параллелограмма внутрь треугольника сохраняет площадь.

### Что Такое Барицентрические Координаты?

Это представление точки через вершины треугольника:

```text
P = alpha * A + beta * B + gamma * C
```

где:

```text
alpha + beta + gamma = 1
alpha, beta, gamma >= 0
```

В нашей записи:

```text
beta = u
gamma = v
alpha = 1 - u - v
```

### Почему Косинусное Распределение Проверяется По `mu`?

Потому что:

```text
mu = cos(theta) = dot(omega, N)
```

Важно: `mu` - это не угол, а косинус угла. Угол `theta` считается от нормали `N` к направлению `omega`. Если преподаватель говорит про угол от плоскости, обозначим его `alpha`; тогда:

```text
alpha = 90 degrees - theta
mu = cos(theta) = sin(alpha)
```

В нашей проверке используется именно `mu`, потому что через скалярное произведение `dot(omega, N)` его можно получить сразу без вычисления самого угла.

Для косинусного распределения теоретическая плотность этой величины:

```text
p(mu) = 2mu
```

Это легко проверить гистограммой.

### Почему `E[mu] = 2/3`?

Потому что:

```text
E[mu] = integral_0^1 mu * p(mu) dmu
E[mu] = integral_0^1 mu * 2mu dmu
E[mu] = 2/3
```

### Что Такое Телесный Угол?

Телесный угол - это трехмерный аналог плоского угла. Он измеряет, какую часть пространства занимает пучок направлений.

На сфере элемент телесного угла:

```text
d omega = sin(theta) dtheta dphi
```

Именно поэтому в задачах с направлениями появляется множитель `sin(theta)`.

### Почему Для Ламберта Плотность Связана С `cos(theta)`?

Ламбертовская модель задает интенсивность:

```text
I(theta) = cos(theta)
```

То есть направления ближе к нормали имеют больший вес. Поэтому выборка направлений должна чаще давать направления около нормали.

### Почему В Косинусном Распределении `p(omega) = cos(theta) / pi`?

Потому что плотность должна интегрироваться в 1 по полусфере:

```text
integral_hemisphere cos(theta) d omega = pi
```

Значит, нормированная плотность:

```text
p(omega) = cos(theta) / pi
```

### Если Спросят "Почему Все Точки Получаются Без Отбрасывания?"

> Для треугольника используется отражение второй половины параллелограмма. Для круга используется прямая формула через обратную функцию распределения радиуса. Для сферы и косинусного распределения тоже используются прямые преобразования случайных чисел. Поэтому число использованных выборок равно числу сформированных точек.

### Если Спросят "Как Доказана Равномерность?"

> Для треугольника равномерность проверяется по одинаковым прямоугольникам, для круга - по равным секторам: равная площадь должна давать близкое число точек. Для сферы проверяется гистограмма `z`, теоретически `p(z)=0.5`. Для косинусного распределения проверяется гистограмма `mu=cos(theta)`, теоретически `p(mu)=2mu`.

### Если Спросят "Почему Ошибки Не Равны Строго Нулю?"

> Из-за конечного числа случайных выборок и погрешностей чисел с плавающей точкой. Геометрические ошибки порядка `1e-17` фактически являются машинной точностью. Ошибки среднего и гистограмм уменьшаются при росте числа выборок.

## Самые Важные Формулы Для Запоминания

Треугольник:

```text
if u + v > 1:
    u = 1 - u
    v = 1 - v

P = A + u(B - A) + v(C - A)
```

Круг:

```text
r = Rc * sqrt(xi)
phi = 2pi * eta
P = C + r cos(phi) T + r sin(phi) B
```

Сфера:

```text
z = 1 - 2xi
phi = 2pi * eta
omega = (sqrt(1 - z^2) cos(phi), sqrt(1 - z^2) sin(phi), z)
```

Косинусное распределение:

```text
r = sqrt(xi)
phi = 2pi * eta
omega_local = (r cos(phi), r sin(phi), sqrt(1 - r^2))
mu = cos(theta) = dot(omega, N)
p(mu) = 2mu
E[mu] = 2/3
```
